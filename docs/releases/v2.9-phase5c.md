# v2.9 Phase 5c — Fact-preserving Quality Optimization

## Why
Phase 5b fixed density compression and ratio calibration, but high-density factual content still exposed quality cliffs:

- Short factual dialogs should often be no-op instead of compressed.
- Technical specs and code reviews lose correctness when values/constants are removed.
- Benchmark QA previously under-counted preserved facts because aliases such as `0.20` vs `20%`, `SE` vs `southeast`, and `< 0` vs `negative` were treated as missing.

## Changes

### Core compressor
- Added fact-density detection for numeric/spec/QA-heavy messages.
- Added fact-preserving compression path:
  - preserve numeric values, units, KV pairs, bullets, arrows, and domain-critical chunks;
  - compact wording without deleting facts;
  - avoid character-level truncation that creates broken tokens such as `compli`.
- Added short fact no-op behavior for ultra-short factual contexts.
- Keep code and high-density specs on quality-first paths.

### Ratio policy
- Raised `SPECS_RATIO` to `0.75` because technical specs have little safe redundancy.

### Benchmark
- Fixed keyword recall alias handling:
  - numeric / percent aliases (`0.20` vs `20%`);
  - spacing/unit aliases (`200ms` vs `200 ms`);
  - containment aliases (`Sarah` vs `Sarah Chen`);
  - direction aliases (`SE` vs `southeast`);
  - compact semantic aliases (`three` vs three listed features, `negative` vs `< 0`, `140K` vs `/ 140`).

## Final benchmark

## Notes
The remaining gap is mostly metric definition rather than functional QA failure. Technical specs already pass 10/10 QA, but entity/number coverage still penalizes compacted representations. Further optimization should add broader real-world benchmarks before tuning more toward benchmark-only scores.
